3.5 - Noah's Notes - Logistic regression from scratch¶

Four months after the supply-prediction project, Minermont Hospital faces a new question: will a patient attend their appointment? Across the hospital about 18% of appointments are missed, and in some specialties up to 27%. Physiotherapy has the highest rate, so the pilot starts there.

This time we do not predict a quantity, like the masks of chapter 2, but a yes/no answer: a binary classification problem. Logistic regression keeps the linear score of linear regression, $z = w \cdot x + b$, and passes it through the sigmoid function, which turns any number into a probability between 0 and 1:

$$\hat{p} = \sigma(z) = \frac{1}{1 + e^{-z}}$$

If $\hat{p}$ is above a threshold (usually 0.5), we predict that the patient will not attend.

In this notebook we build it from scratch with NumPy, just as we did with linear regression:

  1. Import the libraries.
  2. Create a synthetic dataset of Physiotherapy appointments.
  3. Prepare the data: training and test sets, and feature scaling.
  4. Define the sigmoid function.
  5. Define the cost function (cross-entropy, or log loss).
  6. Train the model with gradient descent.
  7. Evaluate it: confusion matrix, sensitivity, specificity, PPV and NPV.
  8. Choose the decision threshold.
  9. Interpret the coefficients.
  10. Predict for new patients.

Step 2: A synthetic dataset of appointments¶

While Martha and Ethan gather the hospital's real attendance records, I am creating a synthetic dataset, as we did in chapter 2. Each row is one Physiotherapy appointment, described by the variables the team considered relevant:

Column Meaning
age Age of the patient (18–85 years)
days_since_last_visit Days since the patient's previous appointment
distance_km Distance from home to the hospital, in km (Minermont serves a rural area)
hour Time of the appointment (8 to 19 h)
first_visit 1 if it is a first visit, 0 if it is a follow-up
previous_no_shows Number of appointments the patient has missed before
no_show Target: 1 if the patient did not attend, 0 if they did

The positive class (1) is the no-show, because it is the event we want to detect. Behind the data there is a hidden rule that we only use to generate the appointments; the model will have to discover the pattern from the examples.

In [2]:
def generate_appointments(n, seed):
    """Synthetic Physiotherapy appointments at Minermont: one row per appointment."""
    rng = np.random.default_rng(seed)
    age = rng.integers(18, 86, n)                                  # years
    days = rng.integers(1, 181, n)                                 # days since the previous appointment
    distance = np.round(rng.gamma(2.0, 6.0, n).clip(0.5, 60), 1)   # km to the hospital (a rural area)
    hour = rng.integers(8, 20, n)                                  # appointment time, from 8:00 to 19:00
    first = rng.binomial(1, 0.35, n)                               # 1 = first visit, 0 = follow-up
    previous = rng.poisson(0.6, n).clip(0, 6)                      # no-shows in the patient's history
    late = np.where(hour >= 17, hour - 16, 0)                      # late-afternoon slots are missed more

    # The hidden rule behind the data. We only use it to generate the appointments:
    # the model never sees it and has to discover the pattern from the examples.
    z = (-1.55 - 0.069 * (age - 50) + 0.026 * (days - 90) + 0.11 * (distance - 12)
         + 1.5 * (previous - 0.6) + 0.56 * (late - 0.75) + 0.63 * (first - 0.35))
    no_show = rng.binomial(1, 1 / (1 + np.exp(-z)))                # 1 = did not attend

    return pd.DataFrame({
        'age': age, 'days_since_last_visit': days, 'distance_km': distance, 'hour': hour,
        'first_visit': first, 'previous_no_shows': previous, 'no_show': no_show,
    })

Step 3: Prepare the data¶

We split the appointments into a training set (75%), which the model learns from, and a test set (25%), which we keep aside to evaluate it on appointments it has never seen. stratify=y keeps the same proportion of no-shows in both sets.

Then we scale the features: we subtract the mean and divide by the standard deviation, so that every variable is measured in "standard deviations". Without this, a variable in km and another in days would have very different sizes and gradient descent would converge slowly. The mean and standard deviation are computed only on the training set and applied to both sets: the test set must not influence training in any way.

Step 4: The sigmoid function¶

The sigmoid $\sigma(z) = \frac{1}{1 + e^{-z}}$ turns the linear score $z$ into a probability: large positive scores give probabilities close to 1, large negative scores give probabilities close to 0, and $z = 0$ gives exactly 0.5, the default threshold.

def sigmoid(z):
    """Maps any real number (or array) to a value between 0 and 1."""
    return 1 / (1 + np.exp(-z))

Step 5: The cost function: cross-entropy (log loss)¶

To measure how wrong the model is we cannot use the mean squared error of chapter 2: with a sigmoid it produces a cost surface with many valleys. Logistic regression uses the cross-entropy, or log loss:

$$J(w, b) = -\frac{1}{m} \sum_{i=1}^{m} \Big[ y_i \log(\hat{p}_i) + (1 - y_i) \log(1 - \hat{p}_i) \Big]$$

For a patient who did not attend ($y = 1$) only the first term counts, $-\log(\hat{p})$: it is almost 0 if the model gave a probability close to 1, and it grows without limit as that probability approaches 0. Confident mistakes are punished hard.

In [7]:
def compute_cost(X, y, w, b):
    """Cross-entropy (log loss) of the model with weights w and bias b."""
    p = sigmoid(X @ w + b)
    p = np.clip(p, 1e-15, 1 - 1e-15)  # avoids log(0)
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

# The cost of a single patient who did NOT attend (y = 1):
for p in [0.9, 0.5, 0.1]:
    print(f"The model predicted p = {p}: cost = {-np.log(p):.3f}")

Step 6: Training with gradient descent¶

The gradients of the cross-entropy have exactly the same form as in linear regression; the only difference is that the prediction now goes through the sigmoid:

$$\frac{\partial J}{\partial w} = \frac{1}{m} X^\top (\hat{p} - y) \qquad \frac{\partial J}{\partial b} = \frac{1}{m} \sum_{i=1}^{m} (\hat{p}_i - y_i)$$

and the update rule is the one we already know: $w := w - \alpha \frac{\partial J}{\partial w}$ and $b := b - \alpha \frac{\partial J}{\partial b}$, where $\alpha$ is the learning rate. Because the features are scaled, a learning rate of 0.1 converges quickly.

In [8]:
def train_logistic(X, y, learning_rate=0.1, num_iterations=3000):
    """Batch gradient descent on the cross-entropy. Returns w, b and the cost of every iteration."""
    m, n = X.shape
    w = np.zeros(n)
    b = 0.0
    costs = []
    for i in range(num_iterations):
        p = sigmoid(X @ w + b)          # a) predict with the current parameters
        dw = (1 / m) * X.T @ (p - y)    # b) gradients
        db = (1 / m) * np.sum(p - y)
        w = w - learning_rate * dw      # c) one step downhill
        b = b - learning_rate * db
        costs.append(compute_cost(X, y, w, b))
        if i % 500 == 0:
            print(f"Iteration {i:4d}: cost = {costs[-1]:.4f}")
    return w, b, costs

Step 7: Evaluating the model¶

With a threshold we turn each probability into a prediction, and comparing the predictions with what really happened gives four possible outcomes, the confusion matrix:

Predicted: will not attend Predicted: will attend
Did not attend True positive (TP) False negative (FN)
Attended False positive (FP) True negative (TN)

From it we compute the metrics used in medicine:

  • Accuracy: $\frac{TP + TN}{\text{total}}$, the share of correct predictions.
  • Sensitivity (recall): $\frac{TP}{TP + FN}$, the share of no-shows that the model detects.
  • Specificity: $\frac{TN}{TN + FP}$, the share of attendances that the model recognises.
  • Positive predictive value (PPV): $\frac{TP}{TP + FP}$, when the model says "will not attend", how often it is right.
  • Negative predictive value (NPV): $\frac{TN}{TN + FN}$, when the model says "will attend", how often it is right.

A useful reference: a "model" that always predicts that every patient will attend already has an accuracy equal to the attendance rate, without detecting a single no-show. Our model has to beat that.

In [9]:
def predict_proba(X, w, b):
    return sigmoid(X @ w + b)

def evaluate(y_true, p, threshold=0.5):
    """Confusion matrix and clinical metrics for a given threshold."""
    y_pred = (p >= threshold).astype(int)
    tp = np.sum((y_pred == 1) & (y_true == 1))
    fn = np.sum((y_pred == 0) & (y_true == 1))
    fp = np.sum((y_pred == 1) & (y_true == 0))
    tn = np.sum((y_pred == 0) & (y_true == 0))
    return {
        'threshold': threshold, 'TP': tp, 'FN': fn, 'FP': fp, 'TN': tn,
        'accuracy': (tp + tn) / len(y_true),
        'sensitivity': tp / (tp + fn),
        'specificity': tn / (tn + fp),
        'PPV': tp / (tp + fp),
        'NPV': tn / (tn + fn),
    }

p_test = predict_proba(X_test_s, w, b)
r = evaluate(y_test, p_test, threshold=0.5)

print("Confusion matrix (test set, threshold 0.5):")
print(f"                  Predicted no-show   Predicted attends")
print(f"  Did not attend  TP = {r['TP']:<14} FN = {r['FN']}")
print(f"  Attended        FP = {r['FP']:<14} TN = {r['TN']}")
print()

Step 8: Choosing the threshold¶

The 0.5 threshold is only a convention. Lowering it makes the model flag more patients as likely no-shows: sensitivity goes up (fewer absences slip through), but so do the false alarms, so specificity and PPV go down. Which balance is better is not a mathematical question but a clinical and organisational one: here a false alarm costs a reminder phone call, while a missed no-show costs an empty slot on a waiting list.

Step 9: Interpreting the coefficients¶

Because the features are scaled, the weights are comparable with each other: each one says how much the log-odds of a no-show change when that variable increases by one standard deviation, with the others fixed. Its exponential, $e^{w}$, is the odds ratio: a value of 2 doubles the odds of a no-show, a value of 0.5 halves them.

The model has found the pattern the team suspected, and the same three variables the book highlights come out on top. Age is the strongest signal: each standard deviation of age (about 20 years) multiplies the odds of a no-show by about 0.28, so older patients miss far fewer appointments. The days since the last visit (×3.2), the previous no-shows (×2.8) and the distance to the hospital (×2.8) raise the risk. The time of the appointment (×1.4) and the type of visit (×1.3) matter less. These are associations learned from the data, not causes: they tell the team whom to call, not why a patient misses an appointment.

Conclusion¶

We have built a logistic regression from scratch: the sigmoid turns a linear score into a probability, the cross-entropy measures the error, and gradient descent adjusts the weights exactly as it did in linear regression.

We have also seen that a classifier is not evaluated with a single number. Accuracy hides the fact that, with the default threshold, many no-shows go undetected; sensitivity, specificity, PPV and NPV tell the whole story, and the threshold lets the team choose the balance that suits the hospital.
