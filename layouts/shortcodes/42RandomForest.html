4.2 - Random forest for emergency triage¶

A single decision tree is easy to read, but it overfits and it is unstable. A random forest trains many different trees and lets them vote: "It's like getting a second, third... a hundredth opinion!", says Claire in the book. It is the model the Minermont team finally chooses for triage. Its key ideas:

  1. Bagging: each tree is trained on a different bootstrap sample of the data.
  2. Feature randomness: at each node a tree only considers a random subset of $m$ features ($m \approx \sqrt{d}$).
  3. The forest predicts the most voted class (the mode of the trees' predictions).
  4. The patients a tree did not see give a free estimate of the error: the out-of-bag (OOB) error.
  5. The forest can estimate the importance of each feature.

Step 2: The triage data¶

The emergency records of a real hospital are confidential, so we generate synthetic patients that behave like the ones in the book. The next cell contains the generator. You do not need to follow it line by line: what matters is that the urgency level comes from a hidden protocol (an early-warning score based on the vital signs, plus some clinical warning signs) and from the nurse's own judgement, which sometimes moves the level one step. The models never see that rule: they have to discover it from the examples.

def generate_patients(n, seed):
    """Synthetic emergency patients at Minermont: one row per patient, with the urgency level assigned at triage."""
    rng = np.random.default_rng(seed)
    age = np.clip(np.round(np.where(rng.random(n) < 0.12, rng.uniform(1, 17, n), rng.normal(52, 20, n))), 1, 97)
    male = rng.binomial(1, 0.5, n)
    s = rng.gamma(0.9, 0.55, n)                        # hidden severity of the episode (never shown to the model)
    infection = rng.binomial(1, 0.12 + 0.1 * (s > 1), n)
    trauma = rng.binomial(1, 0.2, n)
    chest_pain = rng.binomial(1, np.clip(0.04 + 0.0025 * age, 0, 0.35), n)
    dyspnea = rng.binomial(1, np.clip(0.06 + 0.25 * s, 0, 0.9), n)
    vomiting = rng.binomial(1, 0.12, n)
    shock = (rng.random(n) < 0.35) & (s > 1.2)
    hr = 76 + 16 * s + 12 * infection + rng.normal(0, 10, n)
    brady = (rng.random(n) < 0.08) & (s > 1.3)         # a few severe patients have a very slow heart rate
    hr = np.where(brady, rng.normal(42, 6, n), hr)
    rr = 15 + 4.5 * s + 3 * dyspnea + rng.normal(0, 2.2, n)
    spo2 = np.clip(98.2 - 2.2 * s * (0.5 + dyspnea) + rng.normal(0, 1.1, n), 70, 100)
    sbp = np.clip(128 + 0.25 * (age - 50) + rng.normal(0, 16, n) - 28 * s * shock, 60, 230)
    temp = 36.8 + rng.normal(0, 0.35, n) + infection * rng.normal(1.6, 0.6, n)
    p_consc = np.clip(0.02 * s ** 2.2, 0, 0.9)
    consc = np.where(rng.random(n) < p_consc, rng.choice([1, 2, 3], n, p=[0.55, 0.3, 0.15]), 0)
    pain = np.clip(np.round(rng.normal(2.5 + 3.5 * trauma + 3 * chest_pain + 0.8 * s, 1.8, n)), 0, 10).astype(int)
    hr, rr, sbp = np.round(hr).astype(int), np.round(rr).astype(int), np.round(sbp).astype(int)
    temp, spo2 = np.round(temp, 1), np.round(spo2).astype(int)

    # The hidden protocol behind the labels, used only to generate the data:
    # an early-warning score in which a vital sign scores points when it is too low OR too high...
    score = (np.select([rr <= 8, rr <= 11, rr <= 20, rr <= 24], [3, 1, 0, 2], 3)
             + np.select([spo2 <= 91, spo2 <= 93, spo2 <= 95], [3, 2, 1], 0)
             + np.select([sbp <= 90, sbp <= 100, sbp <= 110, sbp <= 219], [3, 2, 1, 0], 3)
             + np.select([hr <= 40, hr <= 50, hr <= 90, hr <= 110, hr <= 130], [3, 1, 0, 1, 2], 3)
             + np.where(consc > 0, 3, 0)
             + np.select([temp <= 35, temp <= 36, temp <= 38, temp <= 39], [3, 1, 0, 1], 2))
    # ...plus clinical discriminators, from the least to the most urgent level
    level = np.full(n, 5)
    level = np.where((score >= 1) | (pain >= 4) | (trauma == 1), 4, level)
    level = np.where((score >= 4) | (pain >= 7) | (temp >= 39) | ((chest_pain == 1) & (age < 45)), 3, level)
    level = np.where((score >= 6) | ((chest_pain == 1) & (age >= 45)) | (spo2 <= 91), 2, level)
    level = np.where((score >= 9) | (consc >= 2) | (sbp <= 80), 1, level)
    # and the nurse's own judgement, which sometimes moves the level one step
    level = np.clip(level + rng.choice([-1, 0, 1], n, p=[0.05, 0.9, 0.05]), 1, 5)

    return pd.DataFrame({
        'age': age.astype(int), 'male': male, 'systolic_bp': sbp, 'heart_rate': hr, 'resp_rate': rr,
        'spo2': spo2, 'temperature': temp, 'consciousness': consc, 'pain': pain, 'chest_pain': chest_pain,
        'dyspnea': dyspnea, 'trauma': trauma, 'vomiting': vomiting, 'level': level,
    })

Step 3: Bootstrap samples¶

A bootstrap sample has the same size as the training set, but it is drawn with replacement: some patients appear several times and others do not appear at all. The probability that a given patient is never chosen in $n$ draws is $(1 - 1/n)^n$, which for large $n$ is about $1/e \approx 0.368$. So each tree sees about 63% of the different patients, and the remaining 37% are its out-of-bag patients.

Step 4: A forest by hand¶

With a bootstrap sample for each tree and max_features='sqrt' (at each node, the tree only looks at a random subset of $\sqrt{13} \approx 3$ features), building a forest takes a few lines. The prediction is the mode of the votes:

$$\hat{C}(x_q) = \text{mode}\{C_1(x_q), C_2(x_q), \dots, C_N(x_q)\}$$

In [5]:
def train_forest(X, y, n_trees, seed=0):
    rng = np.random.default_rng(seed)
    trees = []
    for b in range(n_trees):
        idx = rng.integers(0, len(X), len(X))                                  # bootstrap sample
        tree = DecisionTreeClassifier(max_features='sqrt', random_state=b)      # random features at each node
        trees.append(tree.fit(X.iloc[idx], y.iloc[idx]))
    return trees

def forest_predict(trees, X):
    votes = np.array([tree.predict(X) for tree in trees])                      # trees x patients
    return np.array([np.bincount(v, minlength=6).argmax() for v in votes.T])  # most voted level

single_tree = DecisionTreeClassifier(random_state=0).fit(X_train, y_train)
print(f"A single tree (all the data, all the features): test accuracy {single_tree.score(X_test, y_test):.3f}")
trees = train_forest(X_train, y_train, n_trees=100)
for k in [1, 10, 100]:
    print(f"Forest of {k:>3} tree(s): test accuracy {accuracy_score(y_test, forest_predict(trees[:k], X_test)):.3f}")

A single tree (all the data, all the features): test accuracy 0.730

Forest of   1 tree(s): test accuracy 0.692
Forest of  10 tree(s): test accuracy 0.848
Forest of 100 tree(s): test accuracy 0.875

One tree of the forest is worse than the single full tree (0.692 against 0.730): it has seen only part of the patients, and only a few features at each node. But combining them works: 10 trees reach 0.848 and 100 trees 0.875. Each tree makes different mistakes, and in the vote many of them cancel out.

Step 7: Evaluating a multiclass model¶

Martha insists in the book that overall accuracy is not enough: we need to know how the model behaves with each level, especially the critical ones. In the multiclass confusion matrix the rows are the real classes and the columns the predicted ones. For each class $k$:

  • $TP_k$: the cell $(k, k)$.
  • $FP_k$: the rest of column $k$ (patients of other classes predicted as $k$).
  • $FN_k$: the rest of row $k$ (patients of class $k$ predicted as something else).
  • $TN_k$: all the cells outside row $k$ and column $k$.

$$\text{Precision}_k = \frac{TP_k}{TP_k + FP_k} \qquad \text{Recall}_k = \frac{TP_k}{TP_k + FN_k} \qquad F1_k = 2\,\frac{\text{Precision}_k \cdot \text{Recall}_k}{\text{Precision}_k + \text{Recall}_k}$$

Let's apply the formulas to the 3-level example table in the book:

In [9]:
book_matrix = np.array([[50, 5, 0],      # real Level 1 (high)
                        [8, 200, 15],    # real Level 2 (medium)
                        [1, 25, 500]])   # real Level 3 (low)

def per_class_metrics(cm, names):
    rows = []
    for k, name in enumerate(names):
        tp = cm[k, k]
        fp = cm[:, k].sum() - tp
        fn = cm[k, :].sum() - tp
        tn = cm.sum() - tp - fp - fn
        precision, recall = tp / (tp + fp), tp / (tp + fn)
        rows.append({'class': name, 'TP': tp, 'FP': fp, 'FN': fn, 'TN': tn, 'precision': precision,
                     'recall': recall, 'F1': 2 * precision * recall / (precision + recall)})
    return pd.DataFrame(rows).set_index('class').round(3)

print(per_class_metrics(book_matrix, ['Level 1 (high)', 'Level 2 (medium)', 'Level 3 (low)']).to_string())

Step 8: Feature importance¶

Ethan points out that the forest will not say exactly why it chose Level 2, but it can say which variables are the most decisive. There are two common measures:

  • Impurity-based importance: how much each feature reduces the Gini impurity across all the splits of all the trees. It is free, but it tends to favor features with many different values.
  • Permutation importance, the method described in the book: shuffle the values of one feature among the patients and measure how much the accuracy drops. If the model did not need that feature, the accuracy does not change. We compute it on the test set, repeating each shuffle 10 times.

Both measures agree on the main variables: pain, chest pain, blood pressure, and the respiratory and heart rates. The differences are instructive. Temperature, with many different values, gets a much higher impurity importance (0.087) than permutation importance (0.035). Sex and vomiting, which play no role in the hidden protocol, have a permutation importance of practically zero (slightly negative, by chance). And the level of consciousness looks unimportant only because very few patients have it altered: for them it is decisive, but importance measures the effect over all the patients.

Step 9: The critical levels¶

"This is unacceptable!", exclaims Grace in the book when she sees the recall of the most urgent levels. As Martha explains, the cause is the class imbalance: the model is optimized to get the frequent levels right. The book mentions two remedies, and we try both without touching the test set.

Class weights. With class_weight='balanced' each error on a rare level counts more during training. We compare it with 5-fold cross-validation on the training set. Fully grown trees end in pure leaves, where weights hardly matter, so we also try leaves of at least 10 patients (min_samples_leaf=10):

In [12]:

With larger leaves the weights have more effect (0.695), but the overall accuracy drops to 0.833 and Level 2 gets worse. It is the trade-off the book describes: better recall for the critical levels at the cost of some overall accuracy.

A decision threshold. The forest does not only vote: predict_proba gives the fraction of trees that vote for each level. By default the most voted level wins, but for the critical level we can be more cautious: if at least a fraction $t$ of the trees say Level 1, flag the patient as Level 1. We choose $t$ with the OOB probabilities, which, like the OOB accuracy, only use trees that did not see each patient:

In [13]:
def with_threshold(proba, t):
    pred = rf.classes_[proba.argmax(axis=1)]
    return np.where(proba[:, 0] >= t, 1, pred)          # column 0 = probability of Level 1

oob_proba = rf.oob_decision_function_
rows = []
for t in [0.5, 0.4, 0.3, 0.2, 0.15, 0.1]:
    p = with_threshold(oob_proba, t)
    rows.append({'threshold t': t, 'OOB accuracy': accuracy_score(y_train, p),
                 'recall Level 1': recall_score(y_train, p, average=None)[0],
                 'precision Level 1': precision_score(y_train, p, average=None)[0]})
print(pd.DataFrame(rows).set_index('threshold t').round(3).to_string())

The price is 13 patients flagged as Level 1 who were not (3 with the default rule), an error in the safe direction. As Ethan says in the book, he would rather the system be slightly more cautious and flag high-urgency cases for the nurse to confirm.

Conclusion¶

  • A random forest combines many decision trees trained on bootstrap samples and with random features at each node, and predicts the most voted class. Combining many imperfect, different trees gives a model that is more accurate and much more stable than a single tree.
  • The OOB accuracy estimates the performance on new data during training, and it is a cheap way to choose the number of trees or of features per node.
  • Feature importance, especially by permutation, gives clinicians an interpretable clue about which variables weigh most, and they can compare it with their own knowledge.
  • For the critical levels, overall accuracy is not enough: we have to look at the per-class recall, and use class weights or a more cautious decision threshold, chosen without touching the test set.
  • As in the book, the forest is the most pragmatic choice for triage: accurate, robust and reasonably interpretable, always as a support for the nurse's judgement and never as a replacement.
