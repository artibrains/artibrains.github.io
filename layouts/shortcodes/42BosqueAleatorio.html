4.2 - Bosque aleatorio para el triaje de urgencias¶

Un solo árbol de decisión es fácil de leer, pero se sobreajusta y es inestable. Un bosque aleatorio entrena muchos árboles distintos y los deja votar: "¡Es como pedir una segunda, tercera... centésima opinión!", dice Teresa en el libro. Es el modelo que el equipo de Minermont elige finalmente para el triaje. Sus ideas clave:

  1. Bagging: cada árbol se entrena con una muestra bootstrap distinta de los datos.
  2. Aleatoriedad en las características: en cada nodo, un árbol solo considera un subconjunto aleatorio de $m$ características ($m \approx \sqrt{d}$).
  3. El bosque predice la clase más votada (la moda de las predicciones de los árboles).
  4. Los pacientes que un árbol no ha visto dan una estimación gratuita del error: el error out-of-bag (OOB).
  5. El bosque puede estimar la importancia de cada característica.

En este cuaderno:

Paso 2: Los datos de triaje¶

Los registros de urgencias de un hospital real son confidenciales, así que generamos pacientes sintéticos que se comportan como los del libro. La siguiente celda contiene el generador. No hace falta seguirlo línea a línea: lo importante es que el nivel de urgencia sale de un protocolo oculto (una puntuación de alerta temprana basada en los signos vitales, más algunas señales de alarma clínicas) y del criterio de la propia enfermera, que a veces mueve el nivel un escalón. Los modelos nunca ven esa regla: tienen que descubrirla a partir de los ejemplos.

def generate_patients(n, seed):
    """Pacientes sintéticos de urgencias de Minermont: una fila por paciente, con el nivel de urgencia asignado en el triaje."""
    rng = np.random.default_rng(seed)
    age = np.clip(np.round(np.where(rng.random(n) < 0.12, rng.uniform(1, 17, n), rng.normal(52, 20, n))), 1, 97)
    male = rng.binomial(1, 0.5, n)
    s = rng.gamma(0.9, 0.55, n)                        # gravedad oculta del episodio (el modelo nunca la ve)
    infection = rng.binomial(1, 0.12 + 0.1 * (s > 1), n)
    trauma = rng.binomial(1, 0.2, n)
    chest_pain = rng.binomial(1, np.clip(0.04 + 0.0025 * age, 0, 0.35), n)
    dyspnea = rng.binomial(1, np.clip(0.06 + 0.25 * s, 0, 0.9), n)
    vomiting = rng.binomial(1, 0.12, n)
    shock = (rng.random(n) < 0.35) & (s > 1.2)
    hr = 76 + 16 * s + 12 * infection + rng.normal(0, 10, n)
    brady = (rng.random(n) < 0.08) & (s > 1.3)         # algunos pacientes graves tienen el pulso muy lento
    hr = np.where(brady, rng.normal(42, 6, n), hr)
    rr = 15 + 4.5 * s + 3 * dyspnea + rng.normal(0, 2.2, n)
    spo2 = np.clip(98.2 - 2.2 * s * (0.5 + dyspnea) + rng.normal(0, 1.1, n), 70, 100)
    sbp = np.clip(128 + 0.25 * (age - 50) + rng.normal(0, 16, n) - 28 * s * shock, 60, 230)
    temp = 36.8 + rng.normal(0, 0.35, n) + infection * rng.normal(1.6, 0.6, n)
    p_consc = np.clip(0.02 * s ** 2.2, 0, 0.9)
    consc = np.where(rng.random(n) < p_consc, rng.choice([1, 2, 3], n, p=[0.55, 0.3, 0.15]), 0)
    pain = np.clip(np.round(rng.normal(2.5 + 3.5 * trauma + 3 * chest_pain + 0.8 * s, 1.8, n)), 0, 10).astype(int)
    hr, rr, sbp = np.round(hr).astype(int), np.round(rr).astype(int), np.round(sbp).astype(int)
    temp, spo2 = np.round(temp, 1), np.round(spo2).astype(int)

    # El protocolo oculto detrás de las etiquetas, que solo usamos para generar los datos:
    # una puntuación de alerta temprana en la que un signo vital suma puntos si es demasiado bajo O demasiado alto...
    score = (np.select([rr <= 8, rr <= 11, rr <= 20, rr <= 24], [3, 1, 0, 2], 3)
             + np.select([spo2 <= 91, spo2 <= 93, spo2 <= 95], [3, 2, 1], 0)
             + np.select([sbp <= 90, sbp <= 100, sbp <= 110, sbp <= 219], [3, 2, 1, 0], 3)
             + np.select([hr <= 40, hr <= 50, hr <= 90, hr <= 110, hr <= 130], [3, 1, 0, 1, 2], 3)
             + np.where(consc > 0, 3, 0)
             + np.select([temp <= 35, temp <= 36, temp <= 38, temp <= 39], [3, 1, 0, 1], 2))
    # ...más discriminadores clínicos, del nivel menos urgente al más urgente
    level = np.full(n, 5)
    level = np.where((score >= 1) | (pain >= 4) | (trauma == 1), 4, level)
    level = np.where((score >= 4) | (pain >= 7) | (temp >= 39) | ((chest_pain == 1) & (age < 45)), 3, level)
    level = np.where((score >= 6) | ((chest_pain == 1) & (age >= 45)) | (spo2 <= 91), 2, level)
    level = np.where((score >= 9) | (consc >= 2) | (sbp <= 80), 1, level)
    # y el criterio de la propia enfermera, que a veces mueve el nivel un escalón
    level = np.clip(level + rng.choice([-1, 0, 1], n, p=[0.05, 0.9, 0.05]), 1, 5)

    return pd.DataFrame({
        'edad': age.astype(int), 'hombre': male, 'presion_sistolica': sbp, 'frec_cardiaca': hr, 'frec_respiratoria': rr,
        'spo2': spo2, 'temperatura': temp, 'consciencia': consc, 'dolor': pain, 'dolor_toracico': chest_pain,
        'disnea': dyspnea, 'traumatismo': trauma, 'vomitos': vomiting, 'nivel': level,
    })

Paso 3: Las muestras bootstrap¶

Una muestra bootstrap tiene el mismo tamaño que el conjunto de entrenamiento, pero se extrae con reemplazo: algunos pacientes aparecen varias veces y otros no aparecen. La probabilidad de que un paciente concreto no salga nunca en $n$ extracciones es $(1 - 1/n)^n$, que para $n$ grande vale aproximadamente $1/e \approx 0.368$. Así, cada árbol ve alrededor del 63% de los pacientes distintos, y el 37% restante son sus pacientes out-of-bag (fuera de la bolsa).

Paso 4: Un bosque a mano¶

Con una muestra bootstrap para cada árbol y max_features='sqrt' (en cada nodo, el árbol solo mira un subconjunto aleatorio de $\sqrt{13} \approx 3$ características), construir un bosque son pocas líneas. La predicción es la moda de los votos:

$$\hat{C}(x_q) = \text{moda}\{C_1(x_q), C_2(x_q), \dots, C_N(x_q)\}$$

In [5]:
def train_forest(X, y, n_trees, seed=0):
    rng = np.random.default_rng(seed)
    trees = []
    for b in range(n_trees):
        idx = rng.integers(0, len(X), len(X))                                  # muestra bootstrap
        tree = DecisionTreeClassifier(max_features='sqrt', random_state=b)      # características aleatorias en cada nodo
        trees.append(tree.fit(X.iloc[idx], y.iloc[idx]))
    return trees

def forest_predict(trees, X):
    votes = np.array([tree.predict(X) for tree in trees])                      # árboles x pacientes
    return np.array([np.bincount(v, minlength=6).argmax() for v in votes.T])  # nivel más votado

single_tree = DecisionTreeClassifier(random_state=0).fit(X_train, y_train)
print(f"Un solo árbol (todos los datos, todas las características): exactitud en prueba {single_tree.score(X_test, y_test):.3f}")
trees = train_forest(X_train, y_train, n_trees=100)
for k in [1, 10, 100]:
    print(f"Bosque de {k:>3} árbol(es): exactitud en prueba {accuracy_score(y_test, forest_predict(trees[:k], X_test)):.3f}")

Paso 7: Evaluar un modelo multiclase¶

Marta insiste en el libro en que la exactitud global no basta: necesitamos saber cómo se comporta el modelo con cada nivel, sobre todo con los críticos. En la matriz de confusión multiclase las filas son las clases reales y las columnas las predichas. Para cada clase $k$:

  • $VP_k$: la celda $(k, k)$.
  • $FP_k$: el resto de la columna $k$ (pacientes de otras clases predichos como $k$).
  • $FN_k$: el resto de la fila $k$ (pacientes de la clase $k$ predichos como otra cosa).
  • $VN_k$: todas las celdas fuera de la fila $k$ y de la columna $k$.

$$\text{Precisión}_k = \frac{VP_k}{VP_k + FP_k} \qquad \text{Recall}_k = \frac{VP_k}{VP_k + FN_k} \qquad F1_k = 2\,\frac{\text{Precisión}_k \cdot \text{Recall}_k}{\text{Precisión}_k + \text{Recall}_k}$$

Apliquemos las fórmulas a la tabla de ejemplo con 3 niveles del libro:

In [9]:
book_matrix = np.array([[50, 5, 0],      # nivel real 1 (alto)
                        [8, 200, 15],    # nivel real 2 (medio)
                        [1, 25, 500]])   # nivel real 3 (bajo)

def per_class_metrics(cm, names):
    rows = []
    for k, name in enumerate(names):
        tp = cm[k, k]
        fp = cm[:, k].sum() - tp
        fn = cm[k, :].sum() - tp
        tn = cm.sum() - tp - fp - fn
        precision, recall = tp / (tp + fp), tp / (tp + fn)
        rows.append({'clase': name, 'VP': tp, 'FP': fp, 'FN': fn, 'VN': tn, 'precisión': precision,
                     'recall': recall, 'F1': 2 * precision * recall / (precision + recall)})
    return pd.DataFrame(rows).set_index('clase').round(3)

print(per_class_metrics(book_matrix, ['Nivel 1 (alto)', 'Nivel 2 (medio)', 'Nivel 3 (bajo)']).to_string())

Paso 8: La importancia de las características¶

Víctor señala que el bosque no dirá exactamente por qué eligió el nivel 2, pero sí qué variables son las más decisivas. Hay dos medidas habituales:

  • Importancia por impureza: cuánto reduce cada característica la impureza de Gini en todas las divisiones de todos los árboles. Sale gratis, pero tiende a favorecer las características con muchos valores distintos.
  • Importancia por permutación, el método que describe el libro: barajar los valores de una característica entre los pacientes y medir cuánto baja la exactitud. Si el modelo no necesitaba esa característica, la exactitud no cambia. La calculamos en el conjunto de prueba, repitiendo cada barajado 10 veces.

Paso 9: Los niveles críticos¶

"¡Esto es inaceptable!", exclama Carmen en el libro al ver el recall de los niveles más urgentes. Como explica Marta, la causa es el desbalanceo de clases: el modelo está optimizado para acertar los niveles frecuentes. El libro menciona dos remedios, y probamos los dos sin tocar el conjunto de prueba.

Pesos de las clases. Con class_weight='balanced' cada error en un nivel poco frecuente cuenta más durante el entrenamiento. Lo comparamos con validación cruzada de 5 grupos sobre el conjunto de entrenamiento. Los árboles que crecen del todo terminan en hojas puras, donde los pesos apenas importan, así que probamos también hojas de al menos 10 pacientes (min_samples_leaf=10):

Un umbral de decisión. El bosque no solo vota: predict_proba da la fracción de árboles que votan por cada nivel. Por defecto gana el nivel más votado, pero con el nivel crítico podemos ser más prudentes: si al menos una fracción $t$ de los árboles dice nivel 1, marcar al paciente como nivel 1. Elegimos $t$ con las probabilidades OOB, que, igual que la exactitud OOB, solo usan árboles que no vieron a cada paciente:

def with_threshold(proba, t):
    pred = rf.classes_[proba.argmax(axis=1)]
    return np.where(proba[:, 0] >= t, 1, pred)          # columna 0 = probabilidad del nivel 1

oob_proba = rf.oob_decision_function_
rows = []
for t in [0.5, 0.4, 0.3, 0.2, 0.15, 0.1]:
    p = with_threshold(oob_proba, t)
    rows.append({'umbral t': t, 'exactitud OOB': accuracy_score(y_train, p),
                 'recall nivel 1': recall_score(y_train, p, average=None)[0],

Conclusión¶

  • Un bosque aleatorio combina muchos árboles de decisión entrenados con muestras bootstrap y con características aleatorias en cada nodo, y predice la clase más votada. Combinar muchos árboles imperfectos y distintos da un modelo más exacto y mucho más estable que un solo árbol.
  • La exactitud OOB estima el rendimiento con datos nuevos durante el propio entrenamiento, y es una forma barata de elegir el número de árboles o de características por nodo.
  • La importancia de las características, sobre todo por permutación, da a los clínicos una pista interpretable de qué variables pesan más, y pueden compararla con su propio conocimiento.
  • Con los niveles críticos no basta la exactitud global: hay que mirar el recall por clase y usar pesos de las clases o un umbral de decisión más prudente, elegidos sin tocar el conjunto de prueba.
  • Como en el libro, el bosque es la opción más pragmática para el triaje: exacto, robusto y razonablemente interpretable, siempre como apoyo al criterio de la enfermera y nunca como sustituto.
