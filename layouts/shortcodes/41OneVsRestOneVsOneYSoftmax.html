4.1 - One-vs-Rest, One-vs-One y softmax para el triaje de urgencias¶

En el capítulo 4, el equipo de Minermont quiere sugerir el nivel de urgencia de cada paciente que llega a urgencias, del 1 (rojo, inmediato) al 5 (azul, no urgente). Las herramientas que ya tienen, la regresión logística y las SVM, responden sí o no. Alma explica las dos formas habituales de construir un clasificador de cinco clases a partir de clasificadores binarios, One-vs-Rest (OvR) y One-vs-One (OvO), y el equipo plantea sus puntos débiles: el desbalanceo de "Nivel 1 frente al resto", la ambigüedad cuando ningún clasificador está seguro y los empates en la votación. Carmen concluye que deberían buscar un enfoque que considere todas las clases a la vez. Para los modelos lineales, ese enfoque es la función softmax, la generalización de la sigmoide a varias clases.

En este cuaderno construimos los tres desde cero, con NumPy, y los comparamos con los mismos pacientes:

  1. Importar las bibliotecas.
  2. Los datos de triaje.
  3. La pieza básica: la regresión logística binaria.
  4. One-vs-Rest: cinco clasificadores.
  5. La ambigüedad de One-vs-Rest.
  6. One-vs-One: diez clasificadores y una votación.
  7. Regresión softmax: un solo modelo para los cinco niveles.
  8. Comparación: un paciente, tres respuestas.

Paso 2: Los datos de triaje¶

Los registros de urgencias de un hospital real son confidenciales, así que generamos pacientes sintéticos que se comportan como los del libro. La siguiente celda contiene el generador. No hace falta seguirlo línea a línea: lo importante es que el nivel de urgencia sale de un protocolo oculto (una puntuación de alerta temprana basada en los signos vitales, más algunas señales de alarma clínicas) y del criterio de la propia enfermera, que a veces mueve el nivel un escalón. Los modelos nunca ven esa regla: tienen que descubrirla a partir de los ejemplos.

def generate_patients(n, seed):
    """Pacientes sintéticos de urgencias de Minermont: una fila por paciente, con el nivel de urgencia asignado en el triaje."""
    rng = np.random.default_rng(seed)
    age = np.clip(np.round(np.where(rng.random(n) < 0.12, rng.uniform(1, 17, n), rng.normal(52, 20, n))), 1, 97)
    male = rng.binomial(1, 0.5, n)
    s = rng.gamma(0.9, 0.55, n)                        # gravedad oculta del episodio (el modelo nunca la ve)
    infection = rng.binomial(1, 0.12 + 0.1 * (s > 1), n)
    trauma = rng.binomial(1, 0.2, n)
    chest_pain = rng.binomial(1, np.clip(0.04 + 0.0025 * age, 0, 0.35), n)
    dyspnea = rng.binomial(1, np.clip(0.06 + 0.25 * s, 0, 0.9), n)
    vomiting = rng.binomial(1, 0.12, n)
    shock = (rng.random(n) < 0.35) & (s > 1.2)
    hr = 76 + 16 * s + 12 * infection + rng.normal(0, 10, n)
    brady = (rng.random(n) < 0.08) & (s > 1.3)         # algunos pacientes graves tienen el pulso muy lento
    hr = np.where(brady, rng.normal(42, 6, n), hr)
    rr = 15 + 4.5 * s + 3 * dyspnea + rng.normal(0, 2.2, n)
    spo2 = np.clip(98.2 - 2.2 * s * (0.5 + dyspnea) + rng.normal(0, 1.1, n), 70, 100)
    sbp = np.clip(128 + 0.25 * (age - 50) + rng.normal(0, 16, n) - 28 * s * shock, 60, 230)
    temp = 36.8 + rng.normal(0, 0.35, n) + infection * rng.normal(1.6, 0.6, n)
    p_consc = np.clip(0.02 * s ** 2.2, 0, 0.9)
    consc = np.where(rng.random(n) < p_consc, rng.choice([1, 2, 3], n, p=[0.55, 0.3, 0.15]), 0)
    pain = np.clip(np.round(rng.normal(2.5 + 3.5 * trauma + 3 * chest_pain + 0.8 * s, 1.8, n)), 0, 10).astype(int)
    hr, rr, sbp = np.round(hr).astype(int), np.round(rr).astype(int), np.round(sbp).astype(int)
    temp, spo2 = np.round(temp, 1), np.round(spo2).astype(int)

    # El protocolo oculto detrás de las etiquetas, que solo usamos para generar los datos:
    # una puntuación de alerta temprana en la que un signo vital suma puntos si es demasiado bajo O demasiado alto...
    score = (np.select([rr <= 8, rr <= 11, rr <= 20, rr <= 24], [3, 1, 0, 2], 3)
             + np.select([spo2 <= 91, spo2 <= 93, spo2 <= 95], [3, 2, 1], 0)
             + np.select([sbp <= 90, sbp <= 100, sbp <= 110, sbp <= 219], [3, 2, 1, 0], 3)
             + np.select([hr <= 40, hr <= 50, hr <= 90, hr <= 110, hr <= 130], [3, 1, 0, 1, 2], 3)
             + np.where(consc > 0, 3, 0)
             + np.select([temp <= 35, temp <= 36, temp <= 38, temp <= 39], [3, 1, 0, 1], 2))
    # ...más discriminadores clínicos, del nivel menos urgente al más urgente
    level = np.full(n, 5)
    level = np.where((score >= 1) | (pain >= 4) | (trauma == 1), 4, level)
    level = np.where((score >= 4) | (pain >= 7) | (temp >= 39) | ((chest_pain == 1) & (age < 45)), 3, level)
    level = np.where((score >= 6) | ((chest_pain == 1) & (age >= 45)) | (spo2 <= 91), 2, level)
    level = np.where((score >= 9) | (consc >= 2) | (sbp <= 80), 1, level)
    # y el criterio de la propia enfermera, que a veces mueve el nivel un escalón
    level = np.clip(level + rng.choice([-1, 0, 1], n, p=[0.05, 0.9, 0.05]), 1, 5)

    return pd.DataFrame({
        'edad': age.astype(int), 'hombre': male, 'presion_sistolica': sbp, 'frec_cardiaca': hr, 'frec_respiratoria': rr,
        'spo2': spo2, 'temperatura': temp, 'consciencia': consc, 'dolor': pain, 'dolor_toracico': chest_pain,
        'disnea': dyspnea, 'traumatismo': trauma, 'vomitos': vomiting, 'nivel': level,
    })

Paso 3: La pieza básica: la regresión logística binaria¶

OvR y OvO reutilizan un clasificador binario. Tomamos la regresión logística del capítulo 3: una puntuación lineal $z = \mathbf{w} \cdot \mathbf{x} + b$, la sigmoide $\sigma(z) = \frac{1}{1 + e^{-z}}$ para convertirla en una probabilidad y el descenso del gradiente sobre la pérdida logarítmica. También escribimos una pequeña función que mide, para cada nivel, la proporción de sus pacientes que el modelo asigna al nivel correcto (la sensibilidad o recall de cada clase).

In [5]:
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def train_logistic(Z, t, learning_rate=1.0, iterations=5000):
    """Regresión logística binaria por descenso del gradiente. t vale 1 para la clase positiva y 0 para la negativa."""
    w, b = np.zeros(Z.shape[1]), 0.0
    for _ in range(iterations):
        error = sigmoid(Z @ w + b) - t
        w -= learning_rate * Z.T @ error / len(t)
        b -= learning_rate * error.mean()
    return w, b

def recall_per_level(y_true, y_pred):
    return pd.Series([np.mean(y_pred[y_true == k] == k) for k in levels], index=level_names)

Paso 4: One-vs-Rest: cinco clasificadores¶

Como resume Marta, con cinco niveles OvR entrena cinco modelos: Nivel 1 frente a (2, 3, 4, 5), Nivel 2 frente a (1, 3, 4, 5), y así sucesivamente. Cada uno usa todos los pacientes de entrenamiento, etiquetados con 1 si pertenecen a su nivel y con 0 si no. Para predecir, los cinco clasificadores puntúan al paciente y gana el nivel cuyo clasificador da la puntuación más alta.

Paso 6: One-vs-One: diez clasificadores y una votación¶

OvO entrena un clasificador para cada par de niveles, $\frac{K(K-1)}{2} = \frac{5 \times 4}{2} = 10$, cada uno solo con los pacientes de sus dos niveles. Para predecir, cada clasificador vota por uno de sus dos niveles y gana el nivel con más votos. Luis pregunta qué ocurre si hay un empate. La regla del libro para la regresión logística: elegir, entre los niveles empatados, el que tenga la mayor confianza media en sus victorias.

ovo_models = {}
for i, j in itertools.combinations(levels, 2):
    in_pair = (y_tr == i) | (y_tr == j)                    # solo los pacientes de estos dos niveles
    ovo_models[(i, j)] = train_logistic(Z_train[in_pair], (y_tr[in_pair] == i).astype(float))
    smaller = min(np.sum(y_tr == i), np.sum(y_tr == j)) / in_pair.sum()
    print(f"Nivel {i} frente a nivel {j}: {in_pair.sum():>4} pacientes, el nivel menos frecuente es el {smaller:5.1%}")

votes = np.zeros((len(y_te), 5))
confidence = np.zeros((len(y_te), 5))                        # confianza sumada de las victorias de cada nivel
for (i, j), (w, b) in ovo_models.items():
    p = sigmoid(Z_test @ w + b)                              # probabilidad del nivel i frente al nivel j
    i_wins = p >= 0.5
    votes[i_wins, i - 1] += 1
    votes[~i_wins, j - 1] += 1
    confidence[i_wins, i - 1] += p[i_wins]
    confidence[~i_wins, j - 1] += 1 - p[~i_wins]

most_votes = votes == votes.max(axis=1, keepdims=True)
tied = most_votes.sum(axis=1) > 1
average_confidence = confidence / np.maximum(votes, 1)
ovo_pred = levels[np.where(most_votes, average_confidence, -1).argmax(axis=1)]   # regla de desempate del libro

print(f"\nPacientes con un empate en el máximo de votos: {tied.sum()} de {len(y_te)}")
print(f"Exactitud de OvO en el conjunto de prueba: {np.mean(ovo_pred == y_te):.3f}")
print("Sensibilidad por nivel:")
print(recall_per_level(y_te, ovo_pred).round(3).to_string())

Paso 7: Regresión softmax: un solo modelo para los cinco niveles¶

En lugar de cinco o diez clasificadores separados, un único modelo lineal da a cada paciente cinco puntuaciones a la vez, $z_k = \mathbf{w}_k \cdot \mathbf{x} + b_k$, una por nivel, y la función softmax las convierte en una distribución de probabilidad:

$$\text{Softmax}(z_k) = \frac{e^{z_k}}{\sum_{j=1}^{5} e^{z_j}}$$

Las cinco probabilidades son positivas y suman 1, y los niveles compiten entre sí: subir una puntuación baja la probabilidad de todos los demás. Se entrena, como la capa de salida de las redes neuronales del libro, minimizando la entropía cruzada categórica, el logaritmo negativo de la probabilidad asignada al nivel real:

$$L = -\frac{1}{m} \sum_{i=1}^{m} \log \hat{y}_{i,\,\text{nivel real}}$$

Su gradiente respecto a las puntuaciones tiene la misma forma que en el caso binario: probabilidad menos etiqueta, $\hat{\mathbf{y}} - \mathbf{y}$, donde $\mathbf{y}$ es el nivel real escrito como un vector one-hot (el nivel 3 es $[0, 0, 1, 0, 0]$). Con dos niveles, la regresión softmax es exactamente la regresión logística.

def softmax(scores):
    scores = scores - scores.max(axis=1, keepdims=True)      # las mismas probabilidades, sin desbordar exp
    e = np.exp(scores)
    return e / e.sum(axis=1, keepdims=True)

def cross_entropy(P, y):
    return -np.mean(np.log(P[np.arange(len(y)), y - 1]))

Y_train = np.eye(5)[y_tr - 1]                                # one-hot: nivel 3 -> [0, 0, 1, 0, 0]
W, b = np.zeros((Z_train.shape[1], 5)), np.zeros(5)          # una columna de pesos por nivel
history = []
for iteration in range(5000):
    P = softmax(Z_train @ W + b)
    error = P - Y_train                                      # gradiente de la entropía cruzada respecto a las puntuaciones
    W -= 1.0 * Z_train.T @ error / len(y_tr)
    b -= 1.0 * error.mean(axis=0)
    history.append(cross_entropy(P, y_tr))

softmax_probs = softmax(Z_test @ W + b)
softmax_pred = levels[softmax_probs.argmax(axis=1)]
print(f"Entropía cruzada: {history[0]:.4f} al principio, {history[-1]:.5f} tras {len(history)} iteraciones")
print(f"Suma de las cinco probabilidades: de {softmax_probs.sum(axis=1).min():.6f} a {softmax_probs.sum(axis=1).max():.6f}")
print(f"Exactitud de softmax en el conjunto de prueba: {np.mean(softmax_pred == y_te):.3f}")
print("Sensibilidad por nivel:")
print(recall_per_level(y_te, softmax_pred).round(3).to_string())

Conclusión¶

  • One-vs-Rest construye un clasificador de $K$ clases a partir de $K$ clasificadores binarios. Es sencillo, pero cada clasificador se enfrenta a un problema desbalanceado, sus puntuaciones no suman 1 y una clase situada entre las demás puede quedar aplastada.
  • One-vs-One entrena $K(K-1)/2$ clasificadores con pares más pequeños y más equilibrados, y los deja votar. Aquí necesita el doble de parámetros, y una regla para los empates.
  • La regresión softmax considera todas las clases a la vez, como quería Carmen: un solo modelo, probabilidades que suman 1 y la entropía cruzada como coste. Es la versión multiclase de la regresión logística, y es lo que hace la capa de salida de una red neuronal.
  • Los tres son lineales, y el protocolo de triaje no lo es: un signo vital suma puntos cuando es demasiado bajo o demasiado alto. Por eso el equipo pasó a algoritmos multiclase por naturaleza y no lineales, como los árboles de decisión y los bosques aleatorios, que construyen los siguientes cuadernos de este capítulo.
