3.5 - Notas de Luis - Regresión logística con scikit-learn¶

En el cuaderno Regresión logística desde cero predijimos si un paciente de Fisioterapia faltará a su cita escribiendo nosotros la sigmoide, el coste y el descenso del gradiente. Aquí resolvemos el mismo problema con scikit-learn y añadimos las dos herramientas de este capítulo sin las que un proyecto real no puede funcionar:

  • La regularización, que impide que el modelo memorice los datos de entrenamiento (sobreajuste).
  • La validación cruzada de k grupos, que permite elegir la intensidad de la regularización sin tocar el conjunto de prueba.

Pasos:

  1. Importar las bibliotecas y crear los datos.
  2. Entrenar una regresión logística con scikit-learn.
  3. Evaluarla: matriz de confusión, informe de clasificación y curva ROC.
  4. El sobreajuste: qué ocurre con pocos pacientes y muchas variables.
  5. Regularización L2 y L1.
  6. Elegir $\lambda$ con validación cruzada de k grupos.
  7. Elastic Net y variables correlacionadas.
  8. Clases desbalanceadas.

def generate_appointments(n, seed):
    """Citas sintéticas de Fisioterapia en Minermont: una fila por cita."""
    rng = np.random.default_rng(seed)
    age = rng.integers(18, 86, n)                                  # años
    days = rng.integers(1, 181, n)                                 # días desde la cita anterior
    distance = np.round(rng.gamma(2.0, 6.0, n).clip(0.5, 60), 1)   # km hasta el hospital (zona rural)
    hour = rng.integers(8, 20, n)                                  # hora de la cita, de 8:00 a 19:00
    first = rng.binomial(1, 0.35, n)                               # 1 = primera visita, 0 = revisión
    previous = rng.poisson(0.6, n).clip(0, 6)                      # ausencias en el historial del paciente
    late = np.where(hour >= 17, hour - 16, 0)                      # a última hora de la tarde se falta más

    # La regla oculta detrás de los datos. Solo la usamos para generar las citas:
    # el modelo nunca la ve y tiene que descubrir el patrón a partir de los ejemplos.
    z = (-1.55 - 0.069 * (age - 50) + 0.026 * (days - 90) + 0.11 * (distance - 12)
         + 1.5 * (previous - 0.6) + 0.56 * (late - 0.75) + 0.63 * (first - 0.35))
    no_show = rng.binomial(1, 1 / (1 + np.exp(-z)))                # 1 = no acudió

    return pd.DataFrame({
        'edad': age, 'dias_desde_ultima_cita': days, 'distancia_km': distance, 'hora': hour,
        'primera_visita': first, 'ausencias_previas': previous, 'no_asiste': no_show,
    })

Paso 2: Entrenamiento con scikit-learn¶

Un pipeline encadena el escalado y el modelo en un único objeto. Cuando llamamos a fit, el escalador aprende la media y la desviación típica solo con los datos de entrenamiento, y cuando llamamos a predict, las aplica a los datos nuevos. Así se evita, por construcción, el error de dejar que el conjunto de prueba se filtre en el entrenamiento.

LogisticRegression no usa el descenso del gradiente simple, sino un optimizador más rápido (L-BFGS), y aplica por defecto una regularización L2 ligera (C=1). Con 900 citas y seis variables, sus pesos salen muy parecidos a los que obtuvimos desde cero, y algo más pequeños por esa regularización ligera.

Paso 3: Evaluación¶

predict aplica el umbral de 0,5; predict_proba devuelve las probabilidades, que necesitamos para probar otros umbrales. El informe de clasificación muestra, para cada clase, la precision (lo que llamamos VPP para la clase de ausencias), el recall (la sensibilidad) y el F1-score, que combina ambas.

Atención a la terminología en castellano: accuracy se traduce como exactitud (la proporción total de aciertos), mientras que precision es la precisión en el sentido del VPP. Son métricas distintas.

Paso 4: El sobreajuste¶

En el libro, el primer modelo del hospital era excelente con los datos de entrenamiento y mucho peor con pacientes nuevos: había aprendido las particularidades de los ejemplos de entrenamiento, no el patrón general. Es fácil reproducirlo. Tomamos una muestra pequeña de 300 citas y le añadimos 50 columnas extra que no tienen nada que ver con la asistencia (piensa en todos los demás campos que contiene una historia clínica). La complejidad del modelo crece con el número de variables y, con pocos ejemplos, puede memorizarlas.

Para ver el sobreajuste en estado puro entrenamos con una regularización casi nula (C=10000).

Paso 5: Regularización L2 y L1¶

La regularización añade al coste una penalización que crece con el tamaño de los pesos, de modo que el modelo solo puede usar pesos grandes cuando de verdad reducen el error:

$$J_{L2}(w, b) = \text{log loss} + \lambda \sum_j w_j^2 \qquad\qquad J_{L1}(w, b) = \text{log loss} + \lambda \sum_j |w_j|$$

  • L2 (Ridge) encoge todos los pesos hacia cero, sin anularlos.
  • L1 (Lasso) puede dejar pesos exactamente en cero, así que además selecciona variables.
  • Cuanto mayor es $\lambda$, más fuerte es la regularización. El sesgo $b$ no se penaliza.

Cuidado con la convención de scikit-learn. LogisticRegression no recibe $\lambda$, sino su inversa, C: una C grande significa una regularización débil. Para las fórmulas de arriba, con $m$ ejemplos de entrenamiento, la equivalencia es $C = \frac{1}{2 \lambda m}$ para L2 y $C = \frac{1}{\lambda m}$ para L1.

Un $\lambda$ mayor encoge los pesos y cierra la distancia entre entrenamiento y prueba. Pero ¿qué $\lambda$ usamos? No podemos elegirlo mirando el conjunto de prueba: entonces dejaría de ser "datos no vistos" y nuestra estimación final sería optimista.

Paso 6: Elegir $\lambda$ con validación cruzada de k grupos (las notas de Luis)¶

La validación cruzada de k grupos responde a la pregunta usando solo los datos de entrenamiento:

  1. Dividir el conjunto de entrenamiento en $k$ grupos (folds) de tamaño parecido. Con grupos estratificados, cada grupo conserva la proporción de ausencias.
  2. Para cada valor candidato de $\lambda$, entrenar $k$ veces: cada vez con $k-1$ grupos, validando con el restante.
  3. Promediar las $k$ puntuaciones de validación. Esa media estima cómo se comportará el modelo con datos nuevos.
  4. Elegir el $\lambda$ con la mejor media y volver a entrenar con todo el conjunto de entrenamiento.
  5. Evaluar una sola vez en el conjunto de prueba, que no se ha usado para nada más.

Como recomienda el capítulo, usamos $k = 5$ y una rejilla logarítmica de valores: $\lambda \in \{0.001, 0.01, 0.1, 1, 10, 100, 1000\}$.

La gráfica muestra los dos peligros. A la izquierda ($\lambda$ pequeño), la exactitud de entrenamiento es muy alta, pero la de validación es pobre: sobreajuste. A la derecha ($\lambda$ grande), los pesos quedan aplastados hacia cero y el modelo ya no aprende nada: subajuste. A partir de $\lambda = 1$, las dos curvas se quedan clavadas justo en la exactitud de predecir que todos los pacientes acuden. El mejor valor está en medio.

El capítulo aconseja además refinar la búsqueda alrededor del mejor valor. Probamos algunos valores cercanos y después evaluamos el modelo elegido, una sola vez, en el conjunto de prueba:

Paso 7: Elastic Net y variables correlacionadas¶

Una historia clínica suele guardar la misma información más de una vez. Supongamos que, además de la distancia de casa al hospital, el registro tiene la distancia por carretera y el tiempo de trayecto en coche. Las tres columnas dicen casi lo mismo. El libro recomienda Elastic Net para esta situación, cuando hay variables correlacionadas. Añade al coste las dos penalizaciones:

$$J_{\text{Elastic Net}}(w, b) = \text{log loss} + \lambda_1 \sum_j |w_j| + \lambda_2 \sum_j w_j^2$$

La parte L1 puede seguir eliminando variables, y la parte L2 reparte el peso entre las variables que llevan la misma información. En scikit-learn es penalty='elasticnet' con el optimizador saga, y las dos lambdas se convierten en C y l1_ratio: $C = \frac{1}{m(\lambda_1 + 2\lambda_2)}$ y $\text{l1\_ratio} = \frac{\lambda_1}{\lambda_1 + 2\lambda_2}$.

Volvemos a las 900 citas de entrenamiento del paso 1 y les añadimos las dos columnas nuevas y 20 irrelevantes:

m = len(y_train)   # ahora son 900 citas: l1_model, l2_model y la nueva función lo usan para convertir lambda en C

def elastic_net_model(lam1, lam2):
    return make_pipeline(StandardScaler(),
                         LogisticRegression(C=1 / (m * (lam1 + 2 * lam2)), l1_ratio=lam1 / (lam1 + 2 * lam2),
                                            penalty='elasticnet', solver='saga', max_iter=20000, tol=1e-5, random_state=0))

def mean_validation(model):
    return cross_validate(model, Xg_train, y_train, cv=cv)['test_score'].mean()

                 L1, lambda = 0.01         0.463         0.334             0.000             9             0.840
                L2, lambda = 0.001         0.527         0.553            -0.025            20             0.823

Las tres columnas de distancia tienen correlaciones de entre 0,975 y 0,991. Sin regularización, el modelo reparte la distancia entre ellas de una forma que no tiene sentido: 0,997 para la distancia, 0,520 para la carretera y −0,415 para el tiempo de trayecto, un peso negativo que, por sí solo, significaría que los trayectos largos hacen que los pacientes acudan más. Además, da un peso a las 20 columnas irrelevantes. L2, con la lambda elegida por validación cruzada, 0,001, es muy ligera y apenas cambia ese panorama: el tiempo de trayecto sigue teniendo un pequeño peso negativo, −0,025, y las 20 columnas irrelevantes conservan el suyo. L1 elimina 11 de las 20 columnas irrelevantes y también el tiempo de trayecto, y se queda con 0,463 para la distancia y 0,334 para la carretera. Elastic Net elimina las mismas columnas irrelevantes, quedan 9, y conserva las tres columnas de distancia con pesos positivos: 0,338, 0,335 y 0,103. En el conjunto de prueba, los cuatro modelos están entre 0,823 y 0,840, una diferencia de 5 citas de 300: con 900 citas de entrenamiento, la diferencia está en los pesos, no en la exactitud.

¿Hasta qué punto es estable la elección de L1? Volvemos a entrenar L1 y Elastic Net con 30 muestras bootstrap, cada una formada por 900 citas extraídas al azar, con reemplazo, del conjunto de entrenamiento, y contamos cuántas veces conserva un peso cada columna de distancia:

Qué columna de distancia conserva L1 depende de la muestra: la distancia en 23 de las 30 muestras, la carretera en 22 y el tiempo de trayecto solo en 8. Dos modelos entrenados con casi las mismas citas cuentan historias distintas sobre qué variables importan. Elastic Net conserva la distancia y la carretera en las 30 muestras y el tiempo de trayecto en 26: su parte L2 hace que las columnas correlacionadas se repartan el peso, así que tienden a quedarse juntas en el modelo. Eso es lo que dice el libro: Elastic Net puede seleccionar variables, como L1, y reducir proporcionalmente los pesos de las demás, como L2, y por eso es especialmente útil cuando hay variables correlacionadas.

Paso 8: Clases desbalanceadas¶

Solo alrededor de una cuarta parte de las citas son ausencias, así que el modelo ve muchos más ejemplos de asistencia y tiende a predecirla. Además de mover el umbral, scikit-learn puede ponderar las clases para que cada error en la clase minoritaria cuente más (class_weight='balanced'). Volvemos al conjunto de datos completo:

def sensitivity_specificity(y_true, y_hat):
    tn, fp, fn, tp = confusion_matrix(y_true, y_hat).ravel()
    return tp / (tp + fn), tn / (tn + fp)

balanced = make_pipeline(StandardScaler(), LogisticRegression(class_weight='balanced'))
balanced.fit(X_train, y_train)

Ponderar las clases tiene un efecto parecido a bajar el umbral: se detectan más ausencias a cambio de algo de exactitud. Ambas son formas legítimas de decirle al modelo que no detectar una ausencia nos importa más que hacer una llamada de recordatorio.

Conclusión¶

  • Con scikit-learn, un pipeline de StandardScaler y LogisticRegression reproduce en pocas líneas el modelo que escribimos desde cero.
  • Un clasificador se juzga con la matriz de confusión, el informe de clasificación y la curva ROC, no solo con la exactitud.
  • Con pocos ejemplos y muchas variables el modelo se sobreajusta. La regularización penaliza los pesos grandes: L2 los encoge y L1 puede eliminar variables por completo.
  • Elastic Net combina las dos penalizaciones: elimina variables irrelevantes como L1 y reparte el peso entre variables correlacionadas como L2, a cambio de una segunda $\lambda$ que ajustar.
  • La intensidad de la regularización se elige con validación cruzada de k grupos sobre los datos de entrenamiento. El conjunto de prueba se usa una sola vez, al final.
  • Con clases desbalanceadas, el umbral y los pesos de las clases permiten situar el equilibrio entre sensibilidad y especificidad donde lo necesita el hospital.
