3.5 - Noah's Notes - Logistic regression with scikit-learn¶

In the notebook Logistic regression from scratch we predicted whether a Physiotherapy patient will miss their appointment, writing the sigmoid, the cost and gradient descent ourselves. Here we solve the same problem with scikit-learn, and we add the two tools of this chapter that a real project cannot do without:

  • Regularization, which keeps the model from memorizing the training data (overfitting).
  • k-fold cross-validation, which lets us choose the strength of the regularization without touching the test set.

Steps:

  1. Import the libraries and create the data.
  2. Train a logistic regression with scikit-learn.
  3. Evaluate it: confusion matrix, classification report and ROC curve.
  4. Overfitting: what happens with few patients and many variables.
  5. L2 and L1 regularization.
  6. Choosing $\lambda$ with k-fold cross-validation.
  7. Elastic Net and correlated variables.
  8. Imbalanced classes.

def generate_appointments(n, seed):
    """Synthetic Physiotherapy appointments at Minermont: one row per appointment."""
    rng = np.random.default_rng(seed)
    age = rng.integers(18, 86, n)                                  # years
    days = rng.integers(1, 181, n)                                 # days since the previous appointment
    distance = np.round(rng.gamma(2.0, 6.0, n).clip(0.5, 60), 1)   # km to the hospital (a rural area)
    hour = rng.integers(8, 20, n)                                  # appointment time, from 8:00 to 19:00
    first = rng.binomial(1, 0.35, n)                               # 1 = first visit, 0 = follow-up
    previous = rng.poisson(0.6, n).clip(0, 6)                      # no-shows in the patient's history
    late = np.where(hour >= 17, hour - 16, 0)                      # late-afternoon slots are missed more

    # The hidden rule behind the data. We only use it to generate the appointments:
    # the model never sees it and has to discover the pattern from the examples.
    z = (-1.55 - 0.069 * (age - 50) + 0.026 * (days - 90) + 0.11 * (distance - 12)
         + 1.5 * (previous - 0.6) + 0.56 * (late - 0.75) + 0.63 * (first - 0.35))
    no_show = rng.binomial(1, 1 / (1 + np.exp(-z)))                # 1 = did not attend

    return pd.DataFrame({
        'age': age, 'days_since_last_visit': days, 'distance_km': distance, 'hour': hour,
        'first_visit': first, 'previous_no_shows': previous, 'no_show': no_show,
    })

Step 2: Training with scikit-learn¶

A pipeline chains the scaling and the model into a single object. When we call fit, the scaler learns the mean and the standard deviation from the training data only, and when we call predict, it applies them to the new data. This avoids, by construction, the mistake of letting the test set leak into training.

LogisticRegression does not use plain gradient descent but a faster optimizer (L-BFGS), and it applies a light L2 regularization by default (C=1). With 900 appointments and six variables, its weights come out very close to the ones we obtained from scratch, and slightly smaller because of that light regularization.

The ROC curve shows every threshold at once: for each one it plots the sensitivity (true positive rate) against 1 − specificity (false positive rate). A useless model follows the diagonal; the closer the curve gets to the top-left corner, the better. The area under the curve (AUC) summarizes it in a single number: 0.5 is chance and 1 is perfect. It can also be read as the probability that the model gives a higher score to a random no-show than to a random attendance.

Step 4: Overfitting¶

In the book, the team's first hospital model was excellent on the training data and much worse on new patients: it had learned the particularities of the training examples, not the general pattern. It is easy to reproduce. We take a small sample of 300 appointments and add 50 extra columns that have nothing to do with attendance (think of all the other fields a hospital record contains). The complexity of the model grows with the number of variables, and with few examples it can memorize them.

To see pure overfitting we train with an almost negligible regularization (C=10000).

Step 5: L2 and L1 regularization¶

Regularization adds to the cost a penalty that grows with the size of the weights, so the model can only use large weights when they really reduce the error:

$$J_{L2}(w, b) = \text{log loss} + \lambda \sum_j w_j^2 \qquad\qquad J_{L1}(w, b) = \text{log loss} + \lambda \sum_j |w_j|$$

  • L2 (Ridge) shrinks all the weights towards zero, without cancelling them.
  • L1 (Lasso) can set weights exactly to zero, so it also selects variables.
  • The larger $\lambda$, the stronger the regularization. The bias $b$ is not penalized.

Careful with scikit-learn's convention. LogisticRegression does not take $\lambda$ but its inverse, C: a large C means weak regularization. For the formulas above, with $m$ training examples, the equivalence is $C = \frac{1}{2 \lambda m}$ for L2 and $C = \frac{1}{\lambda m}$ for L1.

In [8]:
m = len(ys_train)

def l2_model(lam):
    return make_pipeline(StandardScaler(), LogisticRegression(C=1 / (2 * lam * m), max_iter=5000))

def l1_model(lam):
    return make_pipeline(StandardScaler(),
                         LogisticRegression(C=1 / (lam * m), penalty='l1', solver='liblinear', max_iter=5000, random_state=0))

A larger $\lambda$ shrinks the weights and closes the gap between training and test. But which $\lambda$ should we use? We cannot choose it by looking at the test set: then the test set would stop being "unseen data" and our final estimate would be optimistic.

Step 6: Choosing $\lambda$ with k-fold cross-validation (Noah's notes)¶

k-fold cross-validation answers the question using only the training data:

  1. Split the training set into $k$ parts (folds) of similar size. With stratified folds each part keeps the proportion of no-shows.
  2. For each candidate value of $\lambda$, train $k$ times: each time on $k-1$ folds, validating on the remaining one.
  3. Average the $k$ validation scores. That average estimates how the model will behave on new data.
  4. Choose the $\lambda$ with the best average and retrain with the whole training set.
  5. Evaluate once on the test set, which has not been used for anything else.

As the chapter recommends, we use $k = 5$ and a logarithmic grid of values: $\lambda \in \{0.001, 0.01, 0.1, 1, 10, 100, 1000\}$.

The plot shows the two dangers. On the left (small $\lambda$) training accuracy is very high but validation is poor: overfitting. L1 has removed most of the variables. The largest weights belong to real ones (days since the last visit, age, previous no-shows, distance), and the few noise columns that survive have small weights: with 50 random columns and only 210 appointments, some of them correlate with attendance by pure chance. Step 7: Elastic Net and correlated variables¶

A hospital record often holds the same information more than once. Suppose that, besides the distance from home to the hospital, the record has the distance by road and the travel time by car. The three columns say almost the same thing. The book recommends Elastic Net for this situation, when there are correlated variables. It adds both penalties to the cost:

$$J_{\text{Elastic Net}}(w, b) = \text{log loss} + \lambda_1 \sum_j |w_j| + \lambda_2 \sum_j w_j^2$$

The L1 part can still remove variables, and the L2 part shares the weight among the variables that carry the same information. In scikit-learn it is penalty='elasticnet' with the saga solver, and the two lambdas become C and l1_ratio: $C = \frac{1}{m(\lambda_1 + 2\lambda_2)}$ and $\text{l1\_ratio} = \frac{\lambda_1}{\lambda_1 + 2\lambda_2}$.

We go back to the 900 training appointments of step 1 and add the two new columns and 20 irrelevant ones:

m = len(y_train)   # 900 appointments now: l1_model, l2_model and the new function use it to convert lambda into C

def elastic_net_model(lam1, lam2):
    return make_pipeline(StandardScaler(),
                         LogisticRegression(C=1 / (m * (lam1 + 2 * lam2)), l1_ratio=lam1 / (lam1 + 2 * lam2),
                                            penalty='elasticnet', solver='saga', max_iter=20000, tol=1e-5, random_state=0))

def mean_validation(model):
    return cross_validate(model, Xg_train, y_train, cv=cv)['test_score'].mean()

grid = [0.001, 0.003, 0.01, 0.03, 0.1]
lam_l1 = max(grid, key=lambda lam: mean_validation(l1_model(lam)))
lam_l2 = max(grid, key=lambda lam: mean_validation(l2_model(lam)))
en_grid = [(lam1, lam2) for lam1 in [0.003, 0.01, 0.03] for lam2 in [0.003, 0.01, 0.03, 0.1]]
lam1, lam2 = max(en_grid, key=lambda lams: mean_validation(elastic_net_model(*lams)))

The three distance columns are correlated between 0.975 and 0.991. Without regularization, the model shares the distance among them in a way that makes no sense: 0.997 for the distance, 0.520 for the road and −0.415 for the travel time, a negative weight that on its own would mean that longer trips make patients more likely to attend. It also gives a weight to all 20 irrelevant columns. L2, with the lambda chosen by cross-validation, 0.001, is very light and barely changes that picture: the travel time still has a small negative weight, −0.025, and the 20 irrelevant columns keep theirs. L1 removes 11 of the 20 irrelevant columns, and it also removes the travel time, keeping 0.463 for the distance and 0.334 for the road. Elastic Net removes as many irrelevant columns, 9 remain, and keeps the three distance columns with positive weights: 0.338, 0.335 and 0.103. On the test set, the four models are between 0.823 and 0.840, a difference of 5 appointments out of 300: with 900 training appointments, the difference is in the weights, not in the accuracy.

Which distance column L1 keeps depends on the sample: the distance in 23 of the 30 samples, the road in 22 and the travel time in only 8. Two models trained on almost the same appointments tell different stories about which variables matter. Elastic Net keeps the distance and the road in all 30 samples and the travel time in 26: its L2 part makes correlated columns share the weight, so they tend to stay in the model together. That is what the book means: Elastic Net can select variables, like L1, and reduce the weights of the others proportionally, like L2, and that is why it is especially useful when there are correlated variables.

Step 8: Imbalanced classes¶

Only about a quarter of the appointments are no-shows, so the model sees many more examples of attendance and leans towards predicting it. Besides moving the threshold, scikit-learn can weight the classes so that each error on the minority class counts more (class_weight='balanced'). Back to the full dataset:

def sensitivity_specificity(y_true, y_hat):
    tn, fp, fn, tp = confusion_matrix(y_true, y_hat).ravel()
    return tp / (tp + fn), tn / (tn + fp)

    print(f"{name:<40} accuracy {accuracy_score(y_test, y_hat):.3f} | sensitivity {sens:.3f} | specificity {spec:.3f}")

Weighting the classes has an effect similar to lowering the threshold: more no-shows detected, at the cost of some accuracy. Both are legitimate ways of telling the model that missing a no-show matters more to us than making a reminder call.

Conclusion¶

  • With scikit-learn, a pipeline of StandardScaler and LogisticRegression reproduces in a few lines the model we wrote from scratch.
  • A classifier is judged on the confusion matrix, the classification report and the ROC curve, not only on accuracy.
  • With few examples and many variables the model overfits. Regularization penalizes large weights: L2 shrinks them and L1 can remove variables altogether.
  • Elastic Net combines both penalties: it removes irrelevant variables like L1 and shares the weight among correlated variables like L2, at the price of a second $\lambda$ to tune.
  • The regularization strength is chosen with k-fold cross-validation on the training data. The test set is used only once, at the end.
  • With imbalanced classes, the threshold and the class weights let us put the balance between sensitivity and specificity where the hospital needs it.
