2.6 - Multiple linear regression: the five-variable mask model¶

In chapter 2, Martha extends the line of linear regression to a plane and, with more variables, to a hyperplane: $\hat{y} = w_1 x_1 + w_2 x_2 + \dots + w_n x_n + b$. Liam brings eighteen months of hospital records, Grace suggests the clinical variables that matter, and the team fits a model that predicts the masks needed each day from five variables: patients, temperature, emergencies, health alerts and weekends.

The other two notebooks of this chapter use a single variable. Here we implement the model with several, the way the book describes it. To be able to check the result, we generate the data from the equation the team obtained in the book, plus some noise, and we see whether each method recovers it:

Step 2: From a line to a hyperplane¶

With several variables, the prediction is a weighted sum: each variable $x_i$ is multiplied by its weight $w_i$ and the bias $b$ is added. Written with vectors, $\hat{y} = \mathbf{w} \cdot \mathbf{x} + b$, which is exactly what NumPy's @ operator computes. Martha's example in the book uses three variables: patients, temperature and the health alert level, with $\hat{y} = 0.6\,x_1 - 0.4\,x_2 + 20\,x_3 + 50$, for a day with 300 patients, 8 °C and no alert:

In [2]:
w = np.array([0.6, -0.4, 20.0])      # masks per patient, per degree, per alert level
b = 50.0                             # the daily baseline
x = np.array([300, 8, 0])            # 300 patients, 8 degrees, no alert

y_hat = w @ x + b
print(f"Predicted masks: {y_hat:.1f}")
print("Term by term:", w * x, "+", b)

Predicted masks: 226.8
Term by term: [180.   -3.2   0. ] + 50.0

226.8 masks: 180 for the 300 patients, −3.2 for the temperature, nothing for the alert, plus the baseline of 50. As Martha says, the decimal does not mean a fraction of a mask; it is an estimate, and in practice the centre would prepare about 227. A prediction with five variables is the same operation with longer vectors.

Step 3: Eighteen months of data¶

Liam's records cover eighteen months. We simulate them, one row per day, with the variables of the model the team fits in the book: the patients seen (fewer at weekends), the temperature (colder in winter), the emergencies (more in winter), three two-week periods of health alert, and whether the day is a weekend. The masks used are generated with the team's equation,

$$\text{masks} = 42.3 + 0.05\,\text{patients} - 0.37\,\text{temperature} + 3.2\,\text{emergencies} + 18.7\,\text{alert} + 4.1\,\text{weekend}$$

plus random noise with a standard deviation of 4 masks. The models will only see the data, never this equation, so we can check afterwards how close each one gets to it.

In [3]:
rng = np.random.default_rng(7)
dates = pd.date_range('2024-01-01', '2025-06-30', freq='D')
n = len(dates)
day_of_year = dates.dayofyear.values
winter = np.cos(2 * np.pi * (day_of_year - 20) / 365)          # 1 in mid-January, -1 in mid-July

weekend = (dates.dayofweek >= 5).astype(int)
temperature = 16 - 8 * winter + rng.normal(0, 2.5, n)
patients = np.where(weekend == 1, rng.normal(245, 18, n), rng.normal(295, 18, n)).round()
emergencies = rng.poisson(np.where(winter > 0.5, 13, 10))
alert = np.zeros(n, dtype=int)
for start in ['2024-01-15', '2024-12-20', '2025-02-03']:
    first = dates.get_loc(pd.Timestamp(start))
    alert[first:first + 14] = 1

book_w = np.array([0.05, -0.37, 3.2, 18.7, 4.1])
book_b = 42.3
X = np.c_[patients, temperature, emergencies, alert, weekend]
masks = X @ book_w + book_b + rng.normal(0, 4, n)

features = ['patients', 'temperature', 'emergencies', 'alert', 'weekend']
data = pd.DataFrame(X, index=dates, columns=features).assign(masks=masks)
print(data.round(1).head())
print(f"\n{n} days, {alert.sum()} of them with a health alert")

Step 4: Training and test months¶

Hazel's rule in chapter 2 is to never evaluate a model on the data it was trained on. With data ordered in time, the honest split is by date: we train on the first fifteen months and keep the last three, which the model will never see, to test it. That is also how the hospital will use it: trained on the past, asked about the future.

Step 5: Gradient descent with Noah's update equations¶

Noah's notes give the update of each weight and of the bias for linear regression with the MSE cost:

$$w_j := w_j - \alpha \, \frac{2}{m} \sum_{i=1}^{m} (\hat{y}^{(i)} - y^{(i)})\, x_j^{(i)} \qquad b := b - \alpha \, \frac{2}{m} \sum_{i=1}^{m} (\hat{y}^{(i)} - y^{(i)})$$

With a matrix $X$ of $m$ rows and one column per variable, the five sums for the weights are a single product, $X^\top (\hat{y} - y)$. First we apply them to the variables as they come. Gradient descent diverges if the learning rate is too large, and with these variables the largest rate that is still stable can be computed: it depends on the biggest variable, the number of patients, which is in the hundreds.

In [6]:
def gradient_descent(X, y, learning_rate, iterations):
    m = len(y)
    w, b = np.zeros(X.shape[1]), 0.0
    for _ in range(iterations):
        error = X @ w + b - y                              # y_hat - y for every day
        w = w - learning_rate * (2 / m) * (X.T @ error)    # Noah's update, all the weights at once
        b = b - learning_rate * (2 / m) * error.sum()
    return w, b

def mse(X, y, w, b):
    return np.mean((X @ w + b - y) ** 2)

A = np.c_[X_train, np.ones(m)]
largest = np.linalg.eigvalsh((2 / m) * A.T @ A).max()
print(f"Largest stable learning rate with the raw variables: {2 / largest:.2e}")

w_raw, b_raw = gradient_descent(X_train, y_train, learning_rate=0.95 * 2 / largest, iterations=5000)
print("\nAfter 5000 iterations at 95% of that rate:")
print("  weights:", w_raw, " bias:", round(b_raw, 2))
print(f"  training MSE: {mse(X_train, y_train, w_raw, b_raw):.2f}")

Largest stable learning rate with the raw variables: 1.24e-05

After 5000 iterations at 95% of that rate:
  weights: [ 0.206 -0.432  3.34   0.201  0.376]  bias: 0.09

The largest stable learning rate is only 1.24e-05, because the patients are in the hundreds while the alert and the weekend are 0 or 1. At that rate, after 5000 iterations, the model is still far from the data: the alert weight is 0.201 instead of about 18, the bias is 0.09 instead of about 44, and the training MSE is 76.17. Each step moves the weight of the patients a lot and the rest hardly at all, so the descent crawls along a long, narrow valley. It is the problem the from-scratch notebook of this chapter solves by scaling its single variable, now with five.

Step 6: Scaling the features¶

Noah's notes warn that gradient descent is sensitive to the scale of the variables, and recommend normalizing the data. We standardize each variable: subtract its mean and divide by its standard deviation, both computed on the training days only. Every variable then has mean 0 and standard deviation 1, the same learning rate suits all the weights, and the descent can take large steps. At the end we convert the weights and the bias back to the original units, so that each weight is again "masks per patient", "masks per degree" and so on:

$$w_j = \frac{w'_j}{\sigma_j} \qquad b = b' - \sum_j \frac{w'_j\,\mu_j}{\sigma_j}$$

In [7]:
mu, sigma = X_train.mean(axis=0), X_train.std(axis=0)
Z_train = (X_train - mu) / sigma

for iterations in [10, 50, 200, 1000]:
    w_s, b_s = gradient_descent(Z_train, y_train, learning_rate=0.1, iterations=iterations)
    print(f"{iterations:>5} iterations: training MSE {mse(Z_train, y_train, w_s, b_s):8.3f}")

w_gd = w_s / sigma                       # back to masks per patient, per degree, ...
b_gd = b_s - np.sum(w_s * mu / sigma)
print("\nWeights in original units:", w_gd, " bias:", round(b_gd, 2))

   10 iterations: training MSE  112.756
   50 iterations: training MSE   15.246
  200 iterations: training MSE   15.238
 1000 iterations: training MSE   15.238

Weights in original units: [ 0.044 -0.374  3.207 18.808  3.363]  bias: 44.3

With the variables standardized, the same function reaches a training MSE of 15.246 in 50 iterations and 15.238 from 200 on, close to the variance of the noise we added (16). Back in the original units, the model needs 0.044 masks per patient, −0.374 per degree, 3.207 per emergency, 18.808 more on an alert day and 3.363 more at weekends, over a base of 44.3.

Step 7: The exact solution: least squares and scikit-learn¶

For linear regression with the MSE cost there is also a direct solution, the least squares method that Martha mentions: the weights that minimize the squared error solve a system of linear equations, the normal equations $(A^\top A)\,\theta = A^\top y$, where $A$ is $X$ with an extra column of ones for the bias. NumPy solves it in one call, and scikit-learn's LinearRegression, which the team uses in the book, does the same inside fit:

In [8]:
theta = np.linalg.lstsq(A, y_train, rcond=None)[0]
model = LinearRegression().fit(X_train, y_train)

table = pd.DataFrame({'book equation': np.r_[book_w, book_b],
                      'gradient descent': np.r_[w_gd, b_gd],
                      'least squares': theta,
                      'scikit-learn': np.r_[model.coef_, model.intercept_]},
                     index=features + ['bias'])
print(table.round(3))

The three methods agree to three decimals, and they are close to the book's equation: 0.044 against 0.05 per patient, −0.374 against −0.37 per degree, 3.207 against 3.2 per emergency, 18.808 against 18.7 for an alert and 44.304 against 42.3 for the bias. The largest difference is the weekend, 3.363 against 4.1: only one day in seven is a weekend, so its weight is estimated from fewer days and the noise shows more in it. With real data there is no equation to compare with, which is why the next step tests the model on days it has not seen.

Step 8: How good is the model?¶

We now use the three test months, which no method has seen. Besides the MSE and the MAE (the mean absolute error, in masks), we compute the coefficient of determination $R^2 = 1 - \frac{\sum (y - \hat{y})^2}{\sum (y - \bar{y})^2}$, the share of the day-to-day variation in masks that the model explains.

Step 9: When the data has errors: MSE or MAE?¶

In the book, the team compares four cost functions and chooses the MSE, with a rule from Noah: if outliers appear, switch to the MAE. The squared error makes a large miss count much more (an error of 10 costs 100, as Martha points out), so a few wrong records can drag the whole model. We add five data-entry errors to the training days, masks typed with an extra zero, and fit the model twice: minimizing the MSE (LinearRegression) and minimizing the MAE (QuantileRegressor with the median, quantile=0.5, and no penalty).

In [10]:
y_typos = y_train.copy()
wrong_days = [40, 130, 222, 300, 390]
y_typos[wrong_days] = y_train[wrong_days] * 10              # e.g. 85 typed as 850
print("Five wrong records:", y_typos[wrong_days].round())

fits = {'MSE, clean data': LinearRegression().fit(X_train, y_train),
        'MSE, with the errors': LinearRegression().fit(X_train, y_typos),
        'MAE, with the errors': QuantileRegressor(quantile=0.5, alpha=0, solver='highs').fit(X_train, y_typos)}
rows = {name: np.r_[f.coef_, f.intercept_, mean_absolute_error(y_test, f.predict(X_test))] for name, f in fits.items()}
print(pd.DataFrame(rows, index=features + ['bias', 'test MAE']).round(3))

Five wrong records out of 456 are enough to ruin the MSE fit: the alert weight falls from 18.808 to 4.373, the weekend weight jumps to 36.153 and the test MAE rises from 2.75 to 11.607 masks. The MAE fit, trained on the same wrong data, stays almost where the clean fit was (alert 18.741, test MAE 2.755). That is Noah's rule in numbers. Even so, the first remedy is to find and correct the wrong records: the MAE limits the damage, it does not tell us where the errors are.

Conclusion¶

  • With several variables, linear regression is still a weighted sum, $\hat{y} = \mathbf{w} \cdot \mathbf{x} + b$: a hyperplane instead of a line, and each weight reads as the effect of one variable when the others do not change.
  • Noah's update equations work unchanged for any number of variables, but only if the variables are on similar scales. Standardizing them turns thousands of useless iterations into a few hundred useful ones.
  • For linear regression, least squares gives the exact answer directly, and scikit-learn uses it. Gradient descent matters because it is the method that also works for the models of the following chapters.
  • The cost function is a decision: the MSE is the usual choice, but a few wrong records can ruin it, and the MAE resists them.
